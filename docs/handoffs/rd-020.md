# rd-020 (rd-nav2-loop-part): the part of the nav2 controller loop that doesn't wait

## What changed
Built on main, independent of rd-near-tolerance (PR #2): nav2 `controller_server` (default Humble DWB) + `planner_server` +
`map_server` params (`validation/nav2/params.yaml`), regressions as overlays on nav2's own parameters
(`nav2/overlays.yaml`), `nav2_tools.py` (overlay, TF rule, map usability check, map cache key; unit-tested offline),
`ci/nav2_replay.launch.py` (goal sender started by launch event handlers) + `ci/nav2_replay_nodes.py` (TF relay, goal
sender), `ci/nav2_replay_once.sh`, `tolerances_nav2.yaml`. `ci/build_map.sh` builds a map with SLAM Toolbox (LGPL-2.1,
CI-time tool from the ROS apt repo; parameters in `nav2/slam_params.yaml`, cache key = recording + params hash).
`gen_recording.sh` now also records `/clock`, saves the sim's own map and writes `goals.yaml`; `setup_ros.sh` gained
`nav2` and `slam` modes. Docs: README section, RECORDINGS.md (maps, SLAM Toolbox license).

## State
`make test` green (offline helpers only). None of the ROS side has run: first CI run is its test (`ros2 bag play --remap`,
the `is_active` wait, DWB defaults, topic remaps are unverified).
